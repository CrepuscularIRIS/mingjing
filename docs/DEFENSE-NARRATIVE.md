## 1. 灵魂句(thesis,业务话不是技术话)

评委的第一个问题一定是:**"这和我直接用 Deep Research / 豆包深度搜索有什么区别?"**

> **「Deep Research 给你一份你只能选择相信的报告;明镜给你一份每条结论都标了可信度、
> 证据不足的会被独立质检当场打回重查、你能亲手点开核验的分析过程。
> 它知道自己什么时候不该自信。」**

**「它知道自己什么时候不该自信」= 整个项目的灵魂句。** 其余所有机制(确定性 QA、verbatim 门、
三档证据、补证回路、WITHHELD 披露、模拟数据不参与分档)都是这句话的证据。

### 30 秒电梯陈述(开场)
> "竞品情报分析师每次分析要花 3–5 天,瓶颈不在找资料,在于**验证结论真的被来源支撑**。
> 大多数 AI 工具生成听起来合理、却无法逐条追溯的报告。明镜的核心约束只有一条:
> **没有结论能进报告,除非它在采集到的来源里有逐字依据**;立不住的,被独立质检打回重新取证,
> 变强了才升级,立不住就如实留存——这就是非伪闭环。"

## 3. 三个诚实性主张:主动叙事化(化把柄为卖点)

### 主张 ① 跑在 MiniMax 而非提供的 Doubao-Seed
- **评委会问:** "为什么没用我们给的模型?合规吗?"
- **主动叙事:**
  > "我们在审计阶段**故意**使用幻觉率更高的 MiniMax-M2.7 作为**压力测试**。确定性 QA 门
  > ——逐字片段比对(HALLUCINATED_SNIPPET)、字面值核查(VALUE_UNSUPPORTED)、证据强度门
  > (WEAK_EVIDENCE)——读的只是**来源文本与 claim 结构,从不读模型自评**,所以它是
  > **provider-agnostic** 的:能在最坏模型下挡住幻觉,换到 Doubao 只会更好。
  > 本次默认旗舰 run 实测:模型 10 条提议被打回 28 次、最终只准入 6 条——这就是压测在工作。"
- **状态(2026-06-10 实弹收口):** 完整 Doubao run `33835db0` 已验证——18 次调用全部指纹 `ep-20260514111325-xjmj7`,5 提议→1 准入(强档,逐字 100%)+4 留存有码,+20% 修正增益、档位跃升。答辩话术升级:「门禁 provider-agnostic 不是声称,是两套模型下的同一行为:MiniMax 高幻觉压测 + 官方豆包实跑,被拒的都有账。」

### 主张 ② 终态全是 partial(没有一条 run 是"完整通过")
- **评委会问:** "run 列表里全是 partial——系统从没完整跑通过一次?"
- **主动叙事:**
  > "partial 是**少而精的设计终态**:确定性 QA 门把证据不足的结论留存为草稿并**如实披露**
  > (WITHHELD + issue code),其余准入。默认旗舰 6/10 准入,被拒的 4 条你能逐条看到为什么。
  > 一个'每次都 100% 通过'的质检门才可疑。" UI 已渲染为「部分准入」+ 解释 tooltip。
- **强档天花板已实弹验证:** Linear 定价 中(2源)→**强(4源)**(≥2 独立可注册域 + 官方源,
  linear.app 官方 + 独立域印证)——强档可达是实测事实。

### 主张 ③ 问卷数据是模拟的(主动先说 > 被发现)
- **评委会问:** "问卷/访谈是真的吗?会不会虚增你的可信度?"
- **主动叙事:**
  > "demo 问卷是**模拟数据,且系统从机制上保证它买不到任何可信度**:fixture 源行标记
  > `SIMULATED`,UI 明示「模拟问卷数据 · 不参与分档」,打分器(`scoring.contributes_to_tier`)
  > 把它从证据分档、佐证计数、矛盾检测**全部排除**——它只演示问卷采集通路(设计→脱敏→入库→
  > 字面值溯源)。有集成测试钉死:一条只有模拟问卷支撑的结论必被 QA 拒绝。真实问卷接入
  > (`INGESTED`)才恢复权威权重。**我们宁可强证据少一档,也不让合成数据铸造可信度。**"
- **真实接入的门已经上线**:`POST /runs/{run_id}/survey/import`(PII 入库前清洗;同一问卷的
  全部回答按 1 个独立信源域计权,杜绝"两个受访者=两个独立域"的虚增)→ 源行标记
  `INGESTED`、UI 显示「真实调研数据」徽章、恢复权威权重——API 测试钉死全链路
  (`tests/test_survey_import_api.py`)。演示中我们**不**向标杆 run 注入自填内容(自己编的
  回答即使走真实门也是合成数据)——这本身就是诚实边界;赛前若采到真实受访者回答,
  现场一条 curl 即可导入并当场看到「真实调研数据」徽章。
- 这是「它知道自己什么时候不该自信」的最硬证据——评委试图揭穿时,发现系统自己早已声明。

## 5. 评委预置问答(anticipated Q&A)

- **Q: 和豆包深度搜索/Deep Research 区别?** → §1 灵魂句。它们给"只能信的报告",我们给"可逐条核验、会自我打回的过程"。
- **Q: 闭环是真的吗,还是自己给自己打分?** → 信息不对称重判:QA 只看证据、判决由**确定性代码规则**算出,不读 LLM 自评。实证:`4fff4227` +42%、2→4 来源、弱→中 + 中→强;trace 里 28 个 qa_fail + 3 个 qa_pass 全程留痕。
- **Q: 为什么结论不是全部通过(6/10)?** → 高门槛诚实:4 条留存逐条披露 issue code;少而精 = QA 在工作。
- **Q: 全部 run 终态都是 partial?** → §3②。
- **Q: 问卷是真的吗?** → §3③(SIMULATED 机制级排除,有集成测试钉死)。
- **Q: 为什么这个 run 跑了 23 分钟?** → 4 轮 QA 打回重采(10 提议→28 次拒绝→6 准入),质量换时间;仍是人工基线(估算)的 42–104×;快速画像 run(`3775d21a`)4分37秒。
- **Q: 强证据出得来吗?** → Linear 定价 中→强(4源,含官方域)——实测,非备弹。
- **Q: 能换行业/竞品吗?** → domain 运行时切换(default/ai_agent/hr)+ Discovery Mode 自动发现竞品,现场可切。
- **Q: 合规?** → robots + SSRF guard + PII scrubber 全链路;COMPLIANCE.md 如实披露。
- **Q: AI 编程工具使用痕迹?** → docs/judge-qa.md TRAE/AI-tooling 节:规格→实现→独立 Codex 审查门禁的全程 AI 协作开发,提交记录可查。
- **Q: 你说的"准确率"怎么算的?分母是什么?** → 三层硬数,口径各自明确:
  ① **QA 判定校准集**:43 个人工标注用例(覆盖全部 6 类 IssueCode 正例 + 干净通过 + 边界近失误),
  确定性 QA 门 admit/withhold 二元判定 **precision 1.00 / recall 1.00 / accuracy 1.00**,0 个已知缺口
  (`tests/test_qa_calibration.py`,任何人可重跑;详见 `docs/qa/CALIBRATION.md`)。
  ② **全量逐字复核**:两个标杆 run 的**全部 10 条准入结论、39 个引用片段**,独立脚本重新对来源原文
  逐字核验,**100% 命中**;5 条留存结论的拒绝原因同样有账(`uv run python scripts/audit_verbatim.py`)。
  ③ **诚实边界**:以上是"被来源逐字支撑率",**不是"对世界为真率"**——来源本身可能错,所以来源按
  可靠性×可信度双轴分级、跨源矛盾会被独立检测并标记。我们不宣称真值,只宣称可溯源、可核验。
- **Q: 来源凭什么分三档?** → 情报界现行标准同源(NATO Admiralty Code / ICD-203):**来源可靠性**
  (独立可注册域名数、官方/调研权威类型)与**信息可信度**(逐字落地、跨源印证/矛盾)**分别评分**
  (不声称两轴正交)。一篇能点开、主题相关的博客**买不到**可信度——这正是前沿 deep-research Agent
  的公认短板:引用链接有效率 >94%,但引用**事实**准确率仅 39–77%(PwC 2026, arXiv 2605.06635)。
  明镜的答案是 verbatim-or-reject:片段不是原文子串,直接拒。
