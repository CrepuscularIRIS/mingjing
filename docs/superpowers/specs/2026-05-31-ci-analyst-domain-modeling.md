## Thesis

> 明镜 is not "an AI that writes competitor reports." It is **a team of AI analysts trained in Competitive Intelligence (CI)**. It uses the discipline's real methods — the Admiralty Code for source/evidence grading, Structured Analytic Techniques (SATs) for reasoning, intelligence-community tradecraft for expressing confidence — so every conclusion is graded, traceable, and defensible.

The depth lives in **domain semantics**, not orchestration. We do not add concurrency, dynamic DAGs, or a heavier runtime (per scope discipline). We add **professional analytic judgment** the agents already have the structure to carry. Every model below is grounded in the LDR research (sources: intelligence tradecraft, OpenCTI/STANAG 2511, Heuer's SATs, ICD 203, CI practice) and maps to a scoring axis.

This is the correct projection of "Gstack/Superpowers-level modeling" onto this task: **process complexity matches task complexity; the depth is in the domain, not the pipeline.**

## The five domain models (grounded, mapped, costed)

### M1 — Evidence strength = Admiralty Code two-axis grading  → 35%
Replaces the ad-hoc 强/中/弱 with the 80-year intelligence standard (NATO STANAG 2511; used by OpenCTI). Two **independent** axes:

- **Source reliability** A (completely reliable) → E (unreliable), **F** = cannot be judged. A property of the *source over time*.
- **Information credibility** 1 (confirmed by other sources) → 5 (improbable), **6** = cannot be judged. A property of *this specific claim*.

So evidence is tagged `B2`, `F4`, `D3`. Computable rule set (from research; the letters/numbers are the standard, the formulas are our design choice):

- **Initial reliability by source type** (never assign A initially — it is earned): official site / signed filing = **B**; reputable trade press / named expert / audited report = **C**; review site / survey / aggregator = **D**; forum / anonymous = **D**; blog / unsourced = **D→E**; unknown new = **F**.
- **Dynamic re-rating (anti-anchoring):** per source keep Beta counts `α`(confirmed)/`β`(refuted) seeded by initial grade; on adjudication bump α or β; **decay both ×0.98/month** (or 24-month window) so old labels don't anchor. `p=α/(α+β)` → letter bands.
- **Credibility by independent corroboration:** `k` independent corroborators, `m` independent contradictors → `1` (k≥2,m=0), `2` (k=1), `3` (k=0, plausible), `4` (m=1), `5` (m≥2), `6` (untestable).
- **Aggregate claim strength (noisy-OR):** numeric maps (A=.95…E=.20; 1=.95,2=.80,3=.60; refute 4=.60,5=.90), independence factor `d`; `S=1−Π(1−support_i)`, `R=1−Π(1−refute_j)`, `Strength=S·(1−R)` → bands very-strong…very-weak.

**Code touch (minimal):** extend `scoring.py` (already computes strong/moderate/weak) with the two-axis grade + noisy-OR; add `reliability`/`info_credibility` columns to `sources`/evidence; frontend shows a `B2` badge per evidence with hover. The demo weak→strong becomes **F4 → B2**, now with 80 years of methodology backing (kills the "拍脑袋/伪闭环" critique).

### M2 — Claim ontology + strength propagation  → 35% + 25%
Today a claim is a flat row. Upgrade to a small **Toulmin-shaped** object and a two-tier ontology:

- Fields: `claim`, `grounds` (evidence ids), `warrant` (the rule linking grounds→claim, e.g. "rising hiring in X signals investment"), `qualifier` (confidence band), `rebuttal` (recorded counter-evidence).
- `claim_type ∈ {fact, synthesis}`. **Synthesis/insight claims** (e.g. "竞品B 在低价挤压中小市场") cite *other claims* via `based_on[]`, not raw sources.
- **Strength propagation** (not averaging): conjunctive (all sub-claims required) → **weakest-link** `min`; disjunctive (any suffices) → noisy-OR over **independent** streams; abductive synthesis → comparative fit vs surviving alternatives. A synthesis claim thus *earns* its confidence from its sub-claims — and insights enter the same traceable, graded chain as facts.

**Code touch:** add `claim_type`, `based_on`, `warrant`, `qualifier` to the claim row (the table is append-only and already JSON-friendly); writer/report render the warrant + qualifier; QA's traceability invariant extends to `based_on`.

### M3 — QA = Quality-of-Information Check (relevance + sufficiency + independence + contradiction)  → 35%
Today QA checks "does the citation exist." Upgrade to the CI standard:

- **Relevance & sufficiency:** does the cited evidence actually support *this* claim, and is there *enough* of it for the asserted strength? (LLM-as-judge with a rubric, single-vote, plus the deterministic substring check already present.)
- **Circular-reporting / corroboration trap:** N sources echoing one origin ≠ N confirmations. Tag each evidence with a `source_independence_group`; same-group items are discounted to ~one stream. **Evaluators almost never expect a student project to handle this.**
- **Contradiction not silenced:** detect rebutting/undercutting evidence, **surface it explicitly** ("来源A说X，来源B说非X"), and *lower* the claim's confidence rather than averaging it away.

**Code touch:** extend `qa/rules.py` (the 6 deterministic rules stay; add a relevance/sufficiency judge + an independence-group check + a contradiction flag). Verdict stays metadata-computed (injection-proof), per the existing design.

### M4 — Analytic output: confidence, BLUF, "so what", gaps, assumptions  → 20% + 25%
Make the report read like a professional intelligence product:

- **Dual-axis confidence** on every judgment: a Word of Estimative Probability (almost certainly / very likely / likely / roughly even / unlikely…) **and** a confidence band (high/moderate/low). Keep the two distinct — conflating them is the classic error.
- **BLUF**: bottom line first → why it matters → 3 key supports → confidence/caveats → recommended actions/watchpoints.
- **"So what" chain:** every insight carries an implication + recommended action (judges are a business team; they want "所以你该调整定价", not "竞品B 定价 $10").
- **Intelligence-gap statement:** the system says what it does *not* know and what would change the judgment (turn the existing `unmet`/coverage-gap into honest analyst language). Near-zero cost, high impression.
- **Key Assumptions Check:** surface the assumptions a synthesis rests on ("假设官网定价为最新"). Cheap (one LLM pass), directly hits "前瞻性".

**Code touch:** synthesis LLM pass over QA-passed claims (the P1 layer) emits BLUF + so-what + gaps + assumptions, each sentence referencing claim ids (traceability invariant extended). Frontend report tab renders it; deterministic claim ledger stays underneath.

### M5 — Schema as a domain profile (not just a field list)  → 20% + 25% 前瞻性
The organizers' "可换行业/可换竞品" answer: a domain isn't only `fields`; it's a **profile** that also encodes *which source types are authoritative for this domain* and *which fields are decision-critical*. SaaS → official pricing page authoritative; HR product → compliance/qualification sources authoritative. This makes the Admiralty initial-reliability map **domain-aware**, which is the professional form of "extensibility."

**Code touch:** extend the existing `domains/*.json` (registry already exists) with `source_weights` and `key_fields`; `scoring.py` reads the active domain's weights. Live "换领域" demo already planned.

## Scope discipline (do NOT build all of it)

Per the standing rule and the research's own warning against false precision and over-engineering, the **main axis + must-haves** are the evidence-credibility spine; the rest is ROADMAP / answered verbally.

**Must-have (the spine, all defensible + visible):**
1. M1 Admiralty two-axis grading (replaces 强/中/弱) — 35%
2. M3 contradiction-not-silenced + relevance/sufficiency QA — 35%
3. M4 dual-axis confidence + BLUF + "so what" + intelligence-gap — 20%+25%
4. M2 synthesis-claim `based_on` + weakest-link/noisy-OR propagation — 35%+25%
5. M5 domain profile (source weights) — extensibility — 20%

**Second tier (only after P0 + front-end + must-haves are green):** ACH evidence×hypothesis matrix; Devil's-Advocate QA (build the strongest counter-case before passing); dynamic source self-calibration (Beta re-rating live); Signposts/time-dimension (snapshot diff over time); a methodology white-paper; intelligence-briefing 答辩 format.

**ROADMAP / verbal only:** full ACH automation, Team A/B, chain-of-custody audit, concurrency.

## Honest caveats (straight from the research — bake into 答辩)
- The Admiralty Code is a **disciplined metadata layer, not a truth machine** — tooling doesn't make grades objective; definitions + review do.
- **Avoid false precision:** show bands (`B2`, "likely / moderate"), not invented decimals like 0.73, when inputs are rough.
- **Independence isn't free:** aggregate over evidentiary *lineages*, not document counts, or you re-introduce the corroboration trap you're claiming to solve.
- **Human-in-the-loop:** position as analyst *augmentation*, not replacement (the existing 人工修正 path is exactly right).

2. **M4 (P1 report)** — LLM synthesis: BLUF + SWOT + 对比分析 + 推荐建议 + so-what + intelligence-gap + Key-Assumptions, every factual sentence claim-cited. *This is the deliverable judges see; lead the demo with it.* → 20%+25%.

4. **M1 shallow** — Admiralty two-axis grade as a **secondary hover badge**; the **primary on-screen label stays 强/中/弱 (or 高/中/低可信)**. Bands only, **no derived decimals on screen** (avoid false-precision / 拍脑袋-dressed-in-math). → 35% (credibility polish).
5. **M5 light** — `source_weights` per domain JSON for the 换领域 answer. → 20%.

**SECOND-TIER (keep as enhancement; do only after must-haves + frontend + P2/P3 are green):**
- Full M1 Admiralty as primary label + Beta dynamic re-rating + temporal decay.
- M2 propagation maths (weakest-link / noisy-OR / abductive). Must-have keeps ONLY `claim_type` + `based_on` so synthesis claims trace.
- Full circular-reporting / source-independence-group discounting (must-have stops at *surfacing* contradiction).
- ACH evidence×hypothesis matrix, Devil's-Advocate QA, Signposts/time-diff, methodology white-paper, intelligence-briefing 答辩 format.

**Demo narrative (both voices):** Collector finds sources → Analyst extracts claims → QA rejects a weak claim → new evidence improves it → Writer produces a board-ready brief → every sentence traces to evidence. Lead with the report; the full CI apparatus is the 答辩 Q&A trump card (earns 技术深度 25% + 答辩 10% *spoken*), not the opening slide.

## Post-v1 follow-ups (from final whole-implementation review, 2026-05-31)

Non-blocking items deferred past the demo (final review found no critical issues; one High — frontend crash on scaffold sentences missing `claim_ids` — was FIXED in commit 3ceb3dd via backend normalization + defensive `CitedSentence`):

- **Uncited scaffold synthesis (Medium, by-design):** `intelligence_gap` / `key_assumptions` sentences may render uncited LLM prose (they are explicitly allowed as scaffolding framing, not factual claims). If a judge probes, frame them as analyst caveats, not evidence-backed assertions. Optionally constrain/template these sections later.
- **Stale synthesis after human correction (Medium):** `POST /runs/{id}/claims/{cid}/correct` does not re-project the persisted synthesis, so a corrected/rejected claim can leave the BLUF/recommendation text stale (citation chips for now-unpassed claims are disabled, but the prose remains). Follow-up: re-project or invalidate `syntheses` on correction, or filter the served synthesis against current passed-claim ids. Edge case for the 3-min demo; correction is a separate demo path.
