# MingJing Launch Film — Voiceover & Captions (两案例版 · ≈6:16)

中文旁白脚本，对齐 20 章两案例结构（案例一 Notion `3775d21a` + 案例二 Notion×Linear
`4fff4227`）。屏上字幕（烧录）已在 `src/timeline.ts` 的 cues 里；本文是**配音逐字稿**。

**旁白 = TTS 自动生成（已就绪，无需自己录音）**：
```bash
./scripts/gen_tts.sh          # edge-tts 逐章生成 public/audio/vo/<id>.mp3（无需 API Key，需联网）
./scripts/render_with_audio.sh  # 自动检测 vo/ 并嵌入，渲染带声音 MP4
```
机制：**逐章生成**，每章一个 mp3，放进该章的 `<Series.Sequence>`，所以旁白随场景播放、
在纯视觉段自然停顿——天然对齐字幕与画面，无累积漂移。已实测每章音频都短于其场景时长（不裁切）。
换音色：`VOICE=zh-CN-XiaoxiaoNeural bash scripts/gen_tts.sh`（女声）。
想自己录音替代某章：把 `public/audio/vo/<id>.mp3` 换成自己的同名文件即可。

## 连续稿（直接通读）

> 明镜不是一个直接生成竞品报告的工具。普通 Deep Research 给你一份只能选择相信的报告，
> 而明镜给你一条可以审计、可以打回、可以追溯的分析链路。
>
> 它把提案和裁定分开：大模型负责提出结论，确定性的质检规则负责裁定真值。证据强度只有
> 强、中、弱三档；没通过质检的结论不会进报告。后端是 FastAPI 加 LangGraph，前端是六标签
> 情报工作台。使用时填一个品类、竞品和目标就能启动，竞品留空就自动发现。
>
> 调研由采集、分析、质检、撰写四类 Agent 协作，传递结构化消息；质检不通过就回边重新取证，
> 通过了才撰写。
>
> 第一个案例是单一竞品 Notion。定价这条结论第一轮没有定价信息、被判弱并打回，重新取证补到
> 五个来源后升级为中，修正增益百分之三十八；整个过程在执行轨迹里可回放。
>
> 第二个案例是 Notion 和 Linear 的对比。修正增益百分之四十二，真闭环印章点亮；十条提议准入
> 六条，留四条并写明原因，引用率百分之百，覆盖率百分之八十。用户口碑从弱（两个来源）升到中
> （四个来源），Linear 定价从中升到强。每条结论都能点开看原始链接、原文片段和 QA 判定；
> Schema 矩阵给出字段完整度，可观测里每个 Agent 的调用和 Token 都有记录。
>
> 这些都能复现地验证：全部准入结论逐字复核百分之百命中，质检校准集准确率百分之百，门禁在
> MiniMax 压测和官方豆包实跑下行为一致。
>
> 一份人工要十几到几十小时的调研，明镜二十三分钟完成，约四十二到一百零四倍提速，全程可回放。
>
> 明镜的目标不是让 AI 更自信，而是让它知道，什么时候不该自信。
